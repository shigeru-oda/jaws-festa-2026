# 秋田県オープンデータの棚卸し

このリポジトリに同梱している秋田県オープンデータの一覧と、年をまたいで形が変わった箇所。
検証の結論（素の S3+Athena と S3 Tables の違い）は [`comparison.md`](comparison.md) にある。
こちらはデータそのものの台帳。

## 出典

秋田県オープンデータポータルサイト <https://opendata.pref.akita.lg.jp/> を加工して作成。
ライセンス: CC BY 4.0 <https://creativecommons.org/licenses/by/4.0/deed.ja>

他都道府県のデータは県ごとにライセンスが異なるため追跡対象外。`.gitignore` で除外し、
集計結果だけを `out/prefecture_comparison.json` に残している。

## 年をまたいで形が変わった3件

### 1. 月報人口 — 36列中26列が改称、位置は不変（本編の第1段）

2020年版と2024年版で列の位置は36列すべて同一、名前だけが26列変わっている。

代表例が転入・転出の系統。

| 位置 | 2020年版 | 2024年版 |
| --- | --- | --- |
| 20 | 県外転入・男女計（人） | 転入・合計（人） |
| 23 | 県内転入・男女計（人） | 転入・県内計（人） |
| 24 | 転入・県外計（人） | 転入・県外計（人）（変更なし） |

位置20 は「県外転入」と名乗っていたが、中身は県内＋県外の合計だった。
2020年版そのもので `位置20 == 位置23 + 位置24` を検算すると、マスク（`***`）の12行を除く
396/396 行で成立する。2024年版でも同じ396/396行で成立。
つまり県は誤った名前を実態に合わせて訂正しただけで、値は動いていない。

位置24 が2020年版の時点で既に「転入・県外計」という正しい名前だったため、
1つのファイルの中に「県外転入」と「転入・県外計」が併存していた。

詳細と過大率の実測は [`comparison.md`](comparison.md) と `out/rename_blindspot.json`。

### 2. 人口移動理由 — 19列→16列、理由が11→8に再編（本編の第2段）

統合・分割・削除が同時に起きている。対応表は [`comparison.md`](comparison.md) の冒頭にある。
値のずれ方の実測は `out/athena_vs_s3tables.json`。

### 3. 年齢各歳 — 128列→127列、途中の1列が消えて以降が全部ずれる（本編では未使用）

2015年版まで位置108にあった `年齢不詳` が2020年版で消え、以降の20列が1つ左にずれている。

| 位置 | 2015年版 | 2020年版 |
| --- | --- | --- |
| 107 | （共通） | （共通） |
| 108 | 年齢不詳 | 0～4歳 |
| 109 | 0～4歳 | 5～9歳 |
| … | 1つずれて続く | |
| 127 | 90～94歳 | 95～99歳 |
| 128 | 95～99歳 | （列なし） |

位置107までは完全一致。2015年版の定義で2020年版を読むと、
年齢階級20列すべてが1つ隣の階級の値を返し、最後の1列が NULL になる。

これは Athena のドキュメントが CSV/TSV について「列を削除する必要があるなら CSV/TSV を使うな」
と明記している、途中の列削除そのもの。第2段（人口移動理由）と同じ壊れ方だが、
ずれるのが連続した年齢階級なので誤りがより自然に見える。本編では使っていない。

## 形以外の不揃い

### 符号化が混在する

同梱25本のうち23本が UTF-8+BOM、2本が CP932。

同じデータセットで版によって変わった例がある。`pref_jyukidaicho_r5.csv` は CP932、
`pref_jyukidaicho_r7.csv` は UTF-8+BOM。年報の更新で符号化が変わっている。

### ヘッダ行がないファイルがある

`pref_jyukidaicho_r5.csv` と `pref_jyukidaicho_r7.csv` は1行目が
`住民基本台帳年報　市町村別人口（令和５年１月１日現在）` というタイトルで、
列名の行がない。Excel から出したままの体裁で、機械可読性が他のファイルと揃っていない。

### 欠測のマスク記号

`***` が使われる。月報人口2020年版の位置23（県内転入）では408行中12行がこれ。
数値として読むと 0 に化けるので、検算するときは除外が必要。
